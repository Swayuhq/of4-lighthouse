Outside Research Connectors

Your research reads four kinds of outside data. None of the four is live yet: two are offered by a provider and wait to be wired, one needs Google's own Places service, and one cannot give rivals' ordinary ads in India. Every read goes through the same connector gateway OF4 uses, so you can build against its answer shape today.

Question 2 · what comes back, and why

What the gateway decides on every call

What your research sends

{
  lead: "analytics",
  channel: "google_places",
  action: "read",
  args: {
    near: { lat: 0, lng: 0 },     // the business location
    radiusMetres: 2000,
    kind: "bakery"
  }
}

Same shape as every OF4 read today (CallRequest in the gateway). Only args differs per source.

What it gets back, one of three

// it worked
{ ok: true, provider: "google", result: Place[] }

// a provider asked us to slow down; try again later
{ ok: false, reason: "...", waitSeconds: 58 }

// refused or broken; the reason is one plain sentence
{ ok: false, reason: "The analytics lead may not send replies." }

Your side handles all three. A wait is not a failure: the source works, read it on the next run.

The place shape Proposal, to agree together

type Place = {
  placeId: string;          // Google's id; the only field we keep long term
  name: string;
  rating?: number;          // 1.0 to 5.0
  reviewCount?: number;
  distanceMetres?: number;
  mapsLink?: string;        // google.com/maps only
  reviews?: { author: string; stars: number; text: string; at: string }[];  // up to 5, credit the author when shown
};

You build against a stub that returns exactly this shape with sample places. When the live Places read lands, nothing on your side changes.

Rules your research meets in swayu-app

Before the data reaches an agent

Rival text is untrusted (rule 8)

Reviews and posts from rivals pass a schema constrained extraction step: closed lists where a field has fixed values, unknown fields rejected, a check for instructions hidden in free text. Only then does an agent read them.

Untrue claims (rule 8b)

A rival's page can carry a false statement that reads like a fact. The research names the page each claim came from, so the owner can open it before trusting it.

Keep only what Google allows

The place id may be kept indefinitely. Treat ratings and reviews as read fresh on each run until the Maps service terms say otherwise. The owner's own review text expires after 30 days.

One way out, one way in

Every outside read goes through the gateway, so permission, budget and ledger apply. A direct call to Google from the research code would bypass all three.
